# LLM MILP Validation

A solver-grounded experimental framework for detecting semantic errors in
optimization models generated by large language models.

This repository is the reproducible implementation artifact and open research repository for the M.Sc. thesis **Validation of AI-generated Optimization Models**, as well as a professional portfolio project. It records benchmark provenance, versioned prompts, provider responses, and experiment metadata so that results can be inspected and reproduced.

## Motivation

LLMs can produce optimization formulations that look plausible while changing the meaning of a natural-language problem. This project develops an auditable experimental workflow for studying those semantic errors in mixed-integer linear programming (MILP) models.

## Research Question

**Working research question:** How effectively can complementary structural, reference-based, solver-grounded, and behavioral validation methods detect semantic errors in AI-generated MILP models?

## Current Status

Phase 0 is complete. The repository currently provides typed benchmark, provider, and prompt contracts; TOML configuration; immutable run artifacts; a deterministic mock provider; and a CLI smoke-test path. No real LLM API, benchmark download, solver execution, or NL4Opt integration is included yet.

## Methodology

The framework keeps benchmark adapters independent from LLM providers. A benchmark case may expose a natural-language description, optional structured data, reference formulation, expected solution or objective, and benchmark metadata. A provider accepts normalized messages and generation settings and returns raw text plus provider, exact model, latency, token, cost, and metadata fields. Versioned prompt protocols and immutable request/response artifacts preserve the conditions of each run. Failures and malformed outputs remain observable rather than being repaired, discarded, or silently retried.

## Repository Structure

```text
src/thesis_bench/       Typed framework package and CLI
tests/                  Automated framework tests
configs/                Human-authored TOML configurations
data/                   Data policy and future benchmark locations
experiments/            Experiment policy and curated manifests/results
docs/                   Methodology and experiment documentation
```

Runtime run directories are ignored under `experiments/*/runs/`. Curated aggregate results and provenance manifests may be committed separately when they are small, reviewable, and licensed for redistribution.

## Reproducibility

Python 3.12 and [uv](https://docs.astral.sh/uv/) are required:

```bash
uv sync
uv run pytest
uv run ruff check .
uv run python -m thesis_bench validate-config configs/mock.toml
uv run python -m thesis_bench dry-run configs/mock.toml --run-id example-run
```

The mock dry run uses synthetic data and a deterministic provider; it makes no network calls. Secrets are never stored in configuration or source files. Future provider adapters must receive environment-variable names and read credentials from the environment.

Artifacts are written beneath `experiments/<experiment_id>/`. Each run contains `request.json`, `response.json`, `raw_response.txt`, and a final `record.json`. A run ID is immutable and an existing run cannot be overwritten.
